## Overview

Xtraq can hydrate input parameters (including UDTTs) before a procedure executes. Resolvers come from your app (claims, DI services, file/DB lookups). Configuration controls **which procedures** opt in.

## Configuration (.xtraqconfig)

```json
{
  "Api": {
    "Mode": "Minimal",
    "Requests": {
      "Hydrate": [
        "@UserId INT",
        "@Entries shared.AuditLogEntryTableType READONLY"
      ],
      "HydrateProcedures": [
        "sample.UserCompositeJsonSnapshot",
        "sample.WriteAuditLogEntries"
      ]
    }
  }
}
```

- `HydrateProcedures` is a case-insensitive allow-list of schema-qualified names; empty = bind all generated procedures. Brackets and extra spaces/tabs are tolerated when matching.
- `HydrateParameters` is informational; resolvers are defined in code, not parsed from this list. Stick to a clear shape like `@Name TYPE [READONLY]`; `READONLY` can be omitted here.

## Service wiring

```csharp
builder.Services.AddHttpContextAccessor();
builder.Services.AddXtraqDbContext(options =>
{
    options.ConnectionString = "...";
    options.ParameterBindings
        .BindScalar<int>("@UserId", (sp, _) =>
        {
            var accessor = sp?.GetService<IHttpContextAccessor>();
            var sub = accessor?.HttpContext?.User?.FindFirstValue("sub");
            return int.TryParse(sub, out var id) ? id : 0;
        }, "sample.UserCompositeJsonSnapshot")
        .BindTable<AuditLogEntryTableType>("@Entries", (sp, _) =>
        {
            if (sp?.GetService<IHttpContextAccessor>()?.HttpContext?.Items is { } items &&
                items.TryGetValue("auditEntries", out var value) &&
                value is IEnumerable<AuditLogEntryTableType> typed)
            {
                return typed;
            }
            return Array.Empty<AuditLogEntryTableType>();
        }, "sample.WriteAuditLogEntries");
});
```

- `BindScalar/BindTable(..., params string[] procedures)` allow per-procedure filters in code (case-insensitive, bracket/whitespace-tolerant).
- Hydration runs only when a binding exists **and** the procedure is allowed (either in `HydrateProcedures` or no allow-list is defined).
- Use the `BindScalarWithInput`/`BindTableWithInput` helpers when bindings need both ambient data (for example from `IHttpContextAccessor`) and request-specific values (`ParameterBindingContext.Input`), such as context TVPs that combine user/app/tenant with per-request record metadata.
- Use the `BindScalarFrom<TInput, TValue>` / `BindTableFrom<TInput, TValue>` helpers when a binding should run only for a specific request/input type; the resolver is skipped when the input type does not match.

## Runtime behavior

- `ProcedureExecutionPlan.EnableParameterBinding` toggles binding per procedure (generator sets this based on `HydrateProcedures`; empty = enabled for all).
- `ParameterBindingEngine` detects structured parameters (`SqlDbType.Structured`/TypeName) and builds TVPs via `TvpHelper`.
- Existing parameter values are never overwritten; only `DBNull`/null slots are filled.
- Procedure parameters flagged with `HasDefaultValue` in the snapshot are generated as nullable request/input properties so you can omit them and let the database default apply. The mapper will not throw for these.
- Output parameters stay output-only unless the stored procedure declares them as `INPUT OUTPUT`. If you want callers to pre-populate those values (for UX defaults or optimistic concurrency tokens), mark the parameter as `INPUT OUTPUT` in T-SQL so the snapshot records it as an input as well; the generator will then surface it on the request/input structs.
- Resolvers are decoupled from `HttpContext`: you get `IServiceProvider` + `CancellationToken` (and the `DbCommand`/input in `ParameterBindingContext`). Use `IHttpContextAccessor` when available, or fall back to other sources (config, files, queues) in non-HTTP hosts.
- Async resolvers (`ValueTask`) are first-class for both scalar and table-valued parameters, and cancellation tokens flow through the binding pipeline.

## Request DTOs (Minimal API)

- For procedures with inputs the generator emits a `<Proc>Request` plus `<Proc>RequestMapper`. Minimal API endpoints (`With<Proc>Procedure`) take the request DTO instead of the raw input struct.
- The mapper hydrates missing values via `ParameterBindingOptions` (`ResolveValueAsync`) before constructing `<Proc>Input`. If a required parameter stays null, it throws an `InvalidOperationException` instead of defaulting to zero/empty.
- Table-valued parameters hydrate as `IReadOnlyList<T>`; bindings fire only when the request leaves the property `null`.
- Streaming helpers also accept request DTO overloads (e.g. `StreamResult...Async(request, onRow, ct)`); the request is mapped and hydrated before streaming starts.
