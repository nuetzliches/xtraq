title: Parameter Binding
description: Configure automatic parameter hydration for generated procedures.

## Overview

Xtraq can hydrate input parameters (including UDTTs) before a procedure executes. Resolvers come from your app (claims, DI services, file/DB lookups). Configuration controls **which procedures** opt in.

## Configuration (.xtraqconfig)

```json
{
  "MinimalApi": {
    "Enabled": true,
    "HydrateParameters": [
      "@UserId INT",
      "@Entries shared.AuditLogEntryTableType READONLY"
    ],
    "HydrateProcedures": [
      "sample.UserCompositeJsonSnapshot",
      "sample.WriteAuditLogEntries"
    ]
  }
}
```

- `HydrateProcedures` is a case-insensitive allow-list of schema-qualified names; empty = bind all generated procedures. Brackets and extra spaces/tabs are tolerated when matching.
- `HydrateParameters` is informational; resolvers are defined in code, not parsed from this list. Stick to a clear shape like `@Name TYPE [READONLY]`; `READONLY` can be omitted here.

## Service wiring

```csharp
builder.Services.AddHttpContextAccessor();
builder.Services.AddXtraqDbContext(options =>
{
    options.ConnectionString = "...";
    options.ParameterBindings
        .BindScalar<int>("@UserId", (sp, _) =>
        {
            var accessor = sp?.GetService<IHttpContextAccessor>();
            var sub = accessor?.HttpContext?.User?.FindFirstValue("sub");
            return int.TryParse(sub, out var id) ? id : 0;
        }, "sample.UserCompositeJsonSnapshot")
        .BindTable<AuditLogEntryTableType>("@Entries", (sp, _) =>
        {
            if (sp?.GetService<IHttpContextAccessor>()?.HttpContext?.Items is { } items &&
                items.TryGetValue("auditEntries", out var value) &&
                value is IEnumerable<AuditLogEntryTableType> typed)
            {
                return typed;
            }
            return Array.Empty<AuditLogEntryTableType>();
        }, "sample.WriteAuditLogEntries");
});
```

- `BindScalar/BindTable(..., params string[] procedures)` allow per-procedure filters in code (case-insensitive, bracket/whitespace-tolerant).
- Hydration runs only when a binding exists **and** the procedure is allowed (either in `HydrateProcedures` or no allow-list is defined).

## Runtime behavior

- `ProcedureExecutionPlan.EnableParameterBinding` toggles binding per procedure (generator sets this based on `HydrateProcedures`; empty = enabled for all).
- `ParameterBindingEngine` detects structured parameters (`SqlDbType.Structured`/TypeName) and builds TVPs via `TvpHelper`.
- Existing parameter values are never overwritten; only `DBNull`/null slots are filled.
