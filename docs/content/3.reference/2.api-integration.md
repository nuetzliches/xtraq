## Service Registration

Start by wiring the generated `IXtraqDbContext` into DI. The same registration works for ASP.NET Core, workers, or CLI hosts.

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddHttpContextAccessor();
builder.Services.AddXtraqDbContext(options =>
{
    options.ConnectionString = builder.Configuration.GetConnectionString("DefaultConnection")
        ?? throw new InvalidOperationException("Missing 'DefaultConnection'.");
    options.CommandTimeout = 60; // optional
});

var app = builder.Build();
```

## Use MapPost with your Stored Procedure

Compare the baseline handler with the Fluent variations via the tabs below.

::Tabs
  :::Tab{label="Standard"}
    ```csharp
    app.MapPost("/orders", async (
        OrderCreateInput input,
        IXtraqDbContext db,
        CancellationToken ct) =>
    {
        var result = await db.OrderCreateAsync(input, ct);
        return TypedResults.Ok(result);
    });
    ```
  :::
  :::Tab{label="Fluent API"}
    ```csharp
    app.MapPost("/orders", async (
        OrderCreateInput input,
        IXtraqDbContext db,
        CancellationToken ct) =>
    {
        var result = await db
            .ConfigureProcedure(input)
            .ExecuteAsync(ctx => ctx.OrderCreateAsync, ct);

        return TypedResults.Ok(result);
    });
    ```
    - `ConfigureProcedure` keeps the handler terse while still giving you access to policies, labels, or streaming helpers later.
  :::
  :::Tab{label="Extended"}
    ```csharp
    app.MapPost("/orders", async (
        OrderCreateInput input,
        IXtraqDbContext db,
        CancellationToken ct) =>
    {
        var result = await db
            .ConfigureProcedure(input)
            .WithLabel("orders.create")
            .WithPolicy(new SampleRetryPolicy())
            .WithTransaction()
            .ExecuteAsync((ctx, payload, ct) => ctx.OrderCreateAsync(payload, ct), ct);

        return TypedResults.Ok(result);
    });
    ```
    - `WithLabel` stamps telemetry/tracing metadata.
    - `WithPolicy` composes retry/timeouts (e.g., `SampleRetryPolicy`).
    - `WithTransaction` ensures the procedure runs inside the generated transaction scope before executing the delegate.
  :::
::

The same selector pattern also works with request DTOs (`ConfigureProcedure<TRequest, TInput>`) or streaming helpers; the tabbed samples simply highlight how you can evolve from the basic handler without changing the HTTP surface.

## Fluent Pipelines in Action

Generated procedures expose `ConfigureProcedure` / `ConfigureProcedureStream` so you can orchestrate execution directly inside CLI commands, hosted services, or HTTP handlers. The tabs contrast the plain helper with Fluent and policy-heavy options.

::Tabs
  :::Tab{label="Standard"}
    ```csharp
    var result = await db.OrderCreateAsync(
        new OrderCreateInput(orderNumber, amount),
        ct);
    ```
  :::
  :::Tab{label="Fluent"}
    ```csharp
    var result = await db
        .ConfigureProcedure(new OrderCreateInput(orderNumber, amount))
        .ExecuteAsync<OrderCreateResult>(ctx => ctx.OrderCreateAsync, ct);
    ```

    - Selector overloads (`ctx => ctx.OrderCreateAsync`) keep handlers short while still returning the unified result type.
  :::
  :::Tab{label="Extended"}
    ```csharp
    var summary = await db
        .ConfigureProcedure(new OrderCreateInput(orderNumber, amount))
        .WithLabel("orders.create")
        .WithPolicy(new SampleRetryPolicy())
        .WithTransaction()
        .ExecuteAsync<OrderCreateResult>((ctx, payload, ct) => ctx.OrderCreateAsync(payload, ct), ct);
    ```

    - `WithTransaction` adds the generated policy that manages scopes/savepoints.
    - `WithPolicy` lets you add retries/timeouts while preserving ordering with other policies.
    - `WithLabel` funnels procedure metadata into logging/tracing.
  :::
::

- Regardless of the tab, the returned `OrderCreateResult` matches the generated helper surface, so downstream code remains untouched.

## Feature Capsules

### Policies & Transactions

```csharp
var pipeline = db.ConfigureProcedure(new UserFindInput(userId))
    .WithLabel("users.find")
    .WithPolicy(new SampleRetryPolicy())
    .WithTransaction();

var favourite = await pipeline
    .WithExecutor((ctx, input, ct) => ctx.UserFindAsync(input, ct))
    .Select(result => result.Result)
    .ExecuteAsync(ct);
```

- Policies run inside out (last added executes first) and receive the `ProcedureExecutionContext`, so they can look at labels or ambient transactions.
- `Select`/`Tap` apply to the in-memory payload only; keep expensive work outside to preserve streaming paths.

### Request DTO Pipelines

Every generated procedure with inputs also ships a request record plus a mapper that hydrates missing values from `IXtraqParameterBindingProvider`.

```csharp
var execution = await db.ConfigureProcedure<OrderStatusRequest, OrderStatusInput>(
    request,
    static (req, ctx, ct) => OrderStatusRequestMapper.ToInputAsync(req, ctx as IXtraqParameterBindingProvider, ct));

var status = await execution
    .ExecuteAsync<OrderStatusResult>((ctx, input, ct) => ctx.OrderStatusAsync(input, ct), ct);
```

- Use this overload whenever the caller only knows about the request DTO (HTTP body, message contract, etc.).
- The mapper enforces required parameters and resolves auto-bound values (claims, table-valued parameters) before the pipeline starts.

### Streaming Without Buffering

```csharp
var streamed = await db.ConfigureProcedureStream<UserListInput, UserListResultSet1Row>(new(includeInactive: false))
    .WithTransaction()
    .WithExecutor((ctx, input, onRow, ct) => ctx.UserList.StreamResultResultSet1Async(input, onRow, ct))
    .ForEach((row, _) => writer.WriteLineAsync(JsonSerializer.Serialize(row)))
    .CompleteWith((output, _) => new ValueTask<int>(output.Count))
    .ExecuteAsync(ct);
```

- Row handlers stay allocation-friendly thanks to the `Func<TRow, CancellationToken, ValueTask>` signature.
- `CompleteWith`, `BufferAsync`, and `AggregateAsync` reuse the same policy chain, so logging/metrics stay consistent across buffered and streaming flows.

### Quick NDJSON Endpoints

Need NDJSON but do not want a bridge? Wire the streaming helper straight into ASP.NET Core:

```csharp
app.MapGet("/orders/stream", async Task StreamOrders(
  HttpContext http, IXtraqDbContext db, CancellationToken ct
) => {
    http.Response.ContentType = "application/x-ndjson";
    await db.OrderList.StreamResultResultSet1Async(
        new OrderListInput(includeInactive: false),
        async (row, ct) =>
        {
            await JsonSerializer.SerializeAsync(http.Response.Body, row, ct);
            await http.Response.Body.WriteAsync("\n"u8, ct);
            await http.Response.Body.FlushAsync(ct);
        },
        ct);
});
```

- Capture output parameters by awaiting the streaming call return value before writing response headers.
- This approach keeps the HTTP handler focused on serialization; all SQL specifics stay inside the generated artifacts.

## Domain DTO Mapping (later enrichment)

Keep orchestration logic light by layering dedicated mappers beside the generated records. `FileMappings` below lives in a separate file and is only used once the projection leaves the Xtraq world.

```csharp
internal static class FileMappings
{
  public static FileResponse Expand(FileFindResultSet1Result row) => new(
    row.fileId,
    row.fileName,
    Normalize(row.contentType),
    row.size,
    Normalize(row.hash));

  public static async Task<FileResponse> ExpandWithContentAsync(this FileResponse summary, string contentPath, CancellationToken ct)
  {
    var bytes = await File.ReadAllBytesAsync(contentPath, ct).ConfigureAwait(false);
    return summary with { Base64Content = Convert.ToBase64String(bytes) };
  }

  private static string? Normalize(string? value) => string.IsNullOrWhiteSpace(value) ? null : value;
}

internal sealed record FileResponse(int FileId, string FileName, string? ContentType, long Size, string? Hash)
{
  public string? Base64Content { get; init; }
}
```

## Pipeline Checklist

1. Keep generated artefacts immutable—extend via partials or external helpers only.
2. Resolve and dispose `IXtraqDbContext` in the same scope you build the pipeline so connection lifetimes stay predictable.
3. Prefer policies over ad-hoc delegates for retries, telemetry, or custom logging.
4. Reach for streaming helpers whenever the procedure exposes them; buffer only when you truly need aggregates.
5. Document the intent of reusable pipelines (extension methods + XML summaries) so other teams immediately see which policies or selectors are in play.
